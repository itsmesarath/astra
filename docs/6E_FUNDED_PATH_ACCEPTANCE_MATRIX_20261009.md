# Future funded-path contract and acceptance matrix

This is a **static, unimplemented proposal** for a later development window. No fixture, test, simulation, accounting event, historical experiment or model call described here has been executed. It does not release a source increment. The current window's 406 Python files stay frozen, and complete suite 6 must be independently accepted first.

The goal is one complete synthetic policy path from one original declared seed. It must recompute each publication using the immediately preceding funded state, rather than discard unaffordable trades from a previously completed unfunded run. Read `6E_FOUR_PUBLICATION_FUNDED_PATH_DESIGN_20261009.md` for causal ordering and scope. These examples do not measure profitability, broker fills, fees or EURUSD CFD economics.

## Proposed complete interface

Retain a fresh exact `NativeFixture`, one exact `DeclaredAdmissionGenesis`, and no supplied previous records, state, packet or completed entry/roundtrip plan. Require `genesis.seed.initialized_at_ns == fixture.start_ns`, held supported dated contract, nonempty synthetic session/scenario/declaration labels, one full contract per candidate/receipt, at most one pending entry or owned position, no partial fills or pyramiding. All prior helper source pins remain unchanged.

Proposed frozen slotted input types:

- `PublishedLiquidityBinding(publication_id, eligible, point, point_sha256)`: exact boolean eligibility, exact independently accepted `SyntheticLiquidityPoint`, and independently retained complete point pin. The exact tuple has one binding per original publication in original order; publication and point identifiers are unique. Features and eligibility are invented caller assertions, not derived or authenticated market data.
- `FundedPathDeclaration(declaration_id, policy_id, exit_plan)`: choose exactly one of the four independent fixed numerical directions and one held time/bracket exit plan. No vote, optimizer, policy fitting or per-publication strategy switch.

Proposed pure APIs are `bindings_sha256`, context-bound `declaration_sha256`, `build_funded_path_plan`, and `verify_funded_path_plan`. Build and verify require original expected fixture, genesis, bindings and declaration pins; verify additionally requires the expected complete plan pin. No default expectations or submitted result is adopted. The precise signatures, source-pin declarations, canonical version/scope strings and full field schemas must be frozen in a separate reviewed implementation contract before any source release.

Metadata preflight checks exact types and complete fields, every pin's syntax, labels, tuple/count bounds, ordered publication-ID binding, timestamp/cursor metadata and timing bounds before quote prices or numeric feature values. Then verify every individual point pin, complete bindings body and complete fixture/genesis/declaration content before the walk. Full-content hashing includes future inputs for identity, but future values cannot influence earlier causal decisions.

Use 1–4 publications at least one second apart, 1–128 complete quotes, at most 20 accounting records, and a proposed 262,144-byte complete canonical-body cap. Bindings body retains the full ordered bindings and selector protocol identity; declaration binds all original contexts and fixed timing, quantity, cadence, denial effects and ID rules; result retains the full output except its own digest. ASCII UTF-8, sorted keys, compact separators, no NaN and complete byte checks precede hashing. A literal protocol limit must not change when a test temporarily lowers a runtime cap. Measure the final largest constructed body, not a partial list or an estimated size, before accepting that limit.

## Selection and event identities

Initial cooldown is the literal timestamp zero, as in the declared original-style policy. Every publication records its supplied eligibility, all four numerical outputs, selected fixed-policy direction, original OPEN native witness, account prefix before and after the decision, cooldown before the decision and immutable first disposition. Later execution never rewrites this audit.

| First disposition, in priority order | New candidate ordinal | New accounting records | Later entry execution |
| --- | --- | --- | --- |
| Ineligible by supplied flag or strict end buffer | None | None | None |
| Inventory blocked, including OPEN, EXIT_PENDING or EXIT_UNKNOWN | None | None | None |
| Pending entry blocked | None | None | None |
| Cooldown | None | None | None |
| No signal | None | None | None |
| Entry selected after available declared budget | Next ordinal | Clock, admission request | Receipt, first-candidate spread refusal or original timeout |
| Budget denied | Next ordinal | Clock, admission request | Not attempted |
| Budget undetermined because margin is absent | Next ordinal | Clock, admission request | Not attempted |

Pending-entry priority remains defensive. Under the proposed at-least-one-second publication cadence, 100 ms entry readiness and quote-effects-before-publication ordering, a later publication's own quote necessarily resolves a pending entry or follows its timeout. A positive public pending-entry disposition is therefore unreachable in a valid complete fixture. Do not violate cadence or bypass the walk to manufacture that coverage.

Only an eligible, unblocked nonzero candidate consumes an ordinal, before budgeting. A liability-blocked budget outcome at this stage is a complete-plan inconsistency, not another disposition. Denial/undetermined outcomes have two records, no pending entry, no receipt, fee, hold or cooldown. Candidate IDs and all event/admission/request/receipt namespaces must be fixed functions of the ordinal only, not of future input pins or prices. A prospective four-digit ordinal template is sufficient for 1–4 candidates; exact literals still need to be locked.

Candidate traces retain the originating publication, ordinal/IDs, initial budget decision and disposition, separated entry outcome/cursor/time, actual hold, exit trigger/cursor/request time, separated exit outcome/cursor/time, and zero-based half-open accounting record indices. Record ranges must be contiguous and cover every record exactly once. Each source-linked record identifies its candidate ordinal and original native publication, quote or CLOSED boundary witness. Blocked publications have equal before/after accounting prefixes and no record range.

## Timing, money and terminal requirements

Use `fixture.end_ns <= native.MAX_INT - 10 seconds` to bound actual outcome-based cooldown. Evaluate strict end eligibility as `now < fixture.end_ns - 18 seconds`; do not construct or clamp an unused out-of-range `now + 18 seconds` for a late ineligible publication. For a publication passing that buffer, pre-price scalar bounds can derive the latest entry deadline at +1.1 seconds, latest actual-entry hold at +16.1 seconds and latest exit deadline at +17.2 seconds, all strictly before fixture end. Actual hold is still derived from the actual entry receipt, not those upper bounds.

Before a later quote, process elapsed original deadlines chronologically. Inclusive execution deadlines close only when the next supplied timestamp is greater; a quote at the deadline is eligible. Hold at H wins before a quote at H, using native coverage through H minus one nanosecond. Consume the quote and its existing entry/exit/bracket effects before evaluating its publication on the original first native cursor, excluding equal-time suffixes. Cooldown begins at actual refusal, original entry-timeout deadline or actual exit receipt; equality permits another candidate. UNKNOWN remains terminal and later quotes/publications only add audit coverage.

Budget snapshots use the complete post-clock prefix immediately preceding their admission request. Their age is zero after the candidate's same-time clock event, even with a zero maximum account-snapshot age. This is an invented accounting cadence, not measured feed freshness. `DeclaredMargin` contains no observation timestamp: retain its original amounts, distinguish missing from zero margin and make no broker margin-freshness claim.

The held loss limit is **net realization loss from the original seed**, including charged entry/exit fees, not the sum of losing trades or peak drawdown. Gains may offset previous losses under that unchanged definition. Only the proposed entry fee changes hypothetical next loss. Reserves, margin and cash buffer are not already charged costs. A valid owned exit is never gated by a later entry loss/funding condition. Monetary overflow or any held accounting failure refuses the whole pure plan; no clipping, skipped trade, partial output, reset or reduced size. Do not reject an idle fixture solely on an unused worst-case price-product estimate.

Complete terminal state must be FLAT or EXIT_UNKNOWN, never pending/OPEN presented as completion. Preserve the prior-event accounting frontier separately from terminal quote coverage and cooldown; no synthetic EOF account clock is added merely to align timestamps. Any liability, including one with zero monetary commitments, keeps complete equity and return null. The exact all-false authority union and complete result schemas remain prospective and must be frozen before implementation.

## Independent timeline oracles

All amounts below are **invented USD micro-units**, not observed dollar costs. Let P be the first original publication, T = 50,000 nanounits be one price tick, and use a fixed nonzero numerical direction only where stated. Unless overridden, use `liquidity_follow`, time exit, entry/exit delay 100 ms, inclusive wait one second, hold 15 seconds, cooldown 10 seconds and a fixture end strictly beyond every eligible publication's 18-second buffer. Every case needs exact complete source/point/context/output pin oracles and all quote/publication/record coverage.

1. **Denial recomputes the path.** Publications P, P+1s, P+2s and P+3s have directions +1, -1, 0 and +1; the last supplied eligibility is false. An initially unaffordable seed produces denied ordinals 1 and 2, then no signal and ineligible: four records, no fees/pending inventory/cooldown. Quote improvement cannot restore flat funding. An unfunded filled path would be inventory-blocked; the new path must not copy its chosen timestamps or trades.
2. **Missing margin is not zero margin.** Two eligible nonzero publications with absent original margin yield two undetermined candidates, fresh ordinals and four records. A separate positive-seed context with explicitly zero margin and zero fees may select an entry. Neither context authenticates broker margin.
3. **Refusal precedes its publication.** Publication 2's first quote at P+1s is the first eligible entry candidate and is widened. Refusal resolves before publication 2, which is cooldown-blocked even with zero signal. Publication 1 remains initially selected; its later refusal belongs only to its candidate trace.
4. **Cooldown equality.** In separate complete fixtures, refusal is at P+100ms and publication 2 occurs at cooldown end minus 1ns, at equality or plus 1ns. Before equality: cooldown, no ordinal; equality/after: candidate ordinal 2 if otherwise eligible and funded. Do not put three publications one nanosecond apart.
5. **Selection priority while owned.** After entry, a supplied-ineligible zero-signal publication is ineligible; eligible zero/nonzero publications are inventory-blocked. Every fixed numerical output remains recorded, but these observations consume no identifier or account clock.
6. **Hold and inclusive widened exit.** Publication 2 at H sees a hold exit request before its quote and is inventory-blocked. Publication 3 at the original exit deadline supplies the first eligible widened exit quote. Settle that crossed price before recording publication 3's cooldown disposition, excluding a favorable later equal-time quote. No second extra-tick monetary charge.
7. **Timeout before the next publication.** No quote exists in the entry interval. Publication 2 at D+1ns first closes the original entry deadline D, retains timeout at D, then is cooldown-blocked. A later publication at cooldown equality permits ordinal 2. A publication quote at D itself cannot be claimed as a no-quote timeout: it is eligible.
8. **UNKNOWN is still inventory.** An entry receives but no quote exists in the exit interval. Close the original exit deadline before a later publication, retain UNKNOWN, then audit favorable quotes/signals without another accounting event. Repeat with zero margin/fees: typed liability still exists and complete equity/return are null.
9. **One seed and realized-loss continuity.** Seed 1,000, entry/exit fees 10/20, first gross realization zero: flat balance 970 and original-seed loss 30. With loss ceiling 30 and otherwise ample required funding, the next proposed entry fee makes hypothetical loss 40 and denies admission. Initial entry's proposed loss 10 passes. No reseeding. Separately test an owned widened exit whose settlement makes cash negative; it must not be suppressed.
10. **Complete capacity.** Four full roundtrips at P+30j seconds for j = 0..3; each entry at +100ms, hold at +15.1s and exit at +15.2s. For a toy tick value 125, arrange each actual crossed exit one favorable tick from entry: cumulative gross 500, entry fees 40, exit fees 80, net +380 from the original seed, all commitments released. Budget snapshots follow clock sequences 1, 6, 11 and 16. Retain all 20 records and exactly 128 quote audits; filler quotes must not create an earlier entry/exit candidate. Require end beyond P+108s and adequate unchanged margin/funding throughout. Measure the full maximum-identifier/full-point/record-link/result body against the proposed cap.
11. **Short and bracket integration.** Use independently complete long and short candidates with fixed bracket exit. The held predicate is favorable crossed-price ticks minus one comparator tick: target at >=3, stop at <=-3, so on grid prices the target starts at four favorable ticks and the stop at two adverse ticks. Test both equalities and their neighboring ticks on both sides. After the trigger, the first eligible delayed exit receives the supplied crossed price, including widening/overshoot; do not settle at the trigger or barrier price or charge the comparator tick again. A quote at H that also crosses a target/stop still follows the winning hold timer and strict-left H-1 boundary. Include short time exit as a separate integrated path: buy at ask, not bid, and reconstruct signed realization and fees manually.
12. **Idle full coverage.** Fixed `no_trade` with four original publications and 128 valid quotes produces zero candidates/records/fees/cooldown changes, all publications and quote audits, FLAT complete equity equal to the original seed and zero net return. Its accounting prefix remains the genesis frontier and `last_event_at_ns` stays null, separately from terminal EOF native coverage. Also use individually valid large price/tick-value inputs for which an unused hypothetical price-product could overflow; no trade means that unused product is never evaluated. This does not permit skipping complete feature, metadata, pin or quote-price validation.
