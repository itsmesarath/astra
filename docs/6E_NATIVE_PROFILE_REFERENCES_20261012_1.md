## Source-derived DBN framing

The metadata prefix contains `DBN`, version byte 3, and a little-endian u32 body length. Absolute offsets: dataset8..24, schema24..26, start26..34, end34..42, limit42..50, stype_in50, stype_out51, ts_out52, symbol string length53..55, reserved55..108, schema-definition length108..112. Count-prefixed symbols/partial/not_found/mappings follow. Mapping dates use YYYYMMDD little-endian u32; groups and intervals retain original order. Version3 metadata body length rounds to a multiple of8. An empty-list header is128bytes including its prefix. These are reference-derived offsets, not a loaded ABI measurement.

The MBO record has a16byte header and56byte base body: length word0, rtype1, publisher2..4, instrument4..8, ts_event8..16, order16..24, signed price24..32, size32..36, flags36, channel37, action38, side39, ts_recv40..48, signed ts_in_delta48..52, sequence52..56. Present ts_out adds8bytes. The official source defines record length in32bit words. Full independent fixtures include target/foreign labels only as bookkeeping; they do not admit a market contract or trading day.

The [native Metadata implementation](https://github.com/databento/dbn/blob/aa012adc6502e01b01d7b5c7836742dde21e93d8/rust/dbn/src/metadata.rs) and [Python getters](https://github.com/databento/dbn/blob/aa012adc6502e01b01d7b5c7836742dde21e93d8/rust/dbn/src/python/metadata.rs) differ from some installed stub annotations: schema is an optional native enum, end/limit are optional nonzero integers, and symbol_cstr_len is exposed. Getter mapping dictionaries can coalesce duplicate raw-symbol groups. The approved contract remains unchanged; any revised native projection must state exact observed type/absence rules, preserve original ordered wire groups and refuse duplicate group keys in the narrow profile.

The [explicit decoder](https://github.com/databento/dbn/blob/aa012adc6502e01b01d7b5c7836742dde21e93d8/python/src/dbn_decoder.rs) uses one state machine; its buffer is not a complete-input validator. [Record getters](https://github.com/databento/dbn/blob/aa012adc6502e01b01d7b5c7836742dde21e93d8/rust/dbn/src/python/record.rs) and [enum definitions](https://github.com/databento/dbn/blob/aa012adc6502e01b01d7b5c7836742dde21e93d8/rust/dbn/src/python/enums.rs) provide independent expected types, names, values, record_size and ts_index. No native encoder output is used as the sole oracle.

## Zstd proof mechanism

The pinned `decode_metadata_symbol` uses UTF-8 decoding followed by trimming trailing NUL bytes; the independent Metadata encoder imposes a narrower ASCII restriction. The explicit UTF8/leap-date literal packet tests decoder behavior only, not encoder admissibility or authentic market symbol syntax. Full raw header and original mapping-group order remain distinct from native getter projections and sorted logical mapping keys.

The pinned `decompressionreader_read` (not `read1`) repeatedly feeds actual source `read(readSize)` chunks until the output request is full, a nonempty frame reaches native end, or source input ends. The registered1/7/65536trace records source read-through, not native consumed offsets. Complete physical framing and the separate same-decoder exact-allocation one-shot check remain mandatory. The pinned one-shot C implementation requires native return0/noextra input on this exact-allocation branch; the harness observes success and entire byte equality, not a directly exposed native status integer. Unknown-FCS shorter-output resize and known-zero shortcuts are not accepted terminal proof paths.

Before a native constructor, a bounded independent parser must cover every magic/header/block/checksum span, reject unsupported/skippable/dictionary modes and malformed tails, and enforce declared window/content limits. Native decoding must then consume every complete frame and compare complete output against the registered independent expectation. Source EOF or an empty native buffer alone is insufficient.

The candidate path uses fixed-size reader buffers and a process committed-memory limit. `decompressobj.write_size` is not a whole-output limit; one-shot `max_output_size` does not bound every known-content-size branch. Documentation and pinned code disagree about `max_window_size` units, so the independent frame-window check is mandatory and the actual native behavior remains a probe. No dictionary-ID field does not authenticate whether the original encoder used a dictionary.

Independent literals include raw AB, RLE A repetition, and compressed blocks with raw/RLE literals and zero sequences. The candidate `28b52ffd20032d00001841424300` is a strict-format negative: compressed block size5 exceeds its declared window3. The valid unknown-size/window1024 counterpart is `28b52ffd00002d00001841424300`. Complete literal bodies and spans live in the separately authored oracle module. Unknown/known-size1MiB and1MiB+1 RLE frames exercise expansion boundaries without a native encoder.

Compressed sequence/Huffman paths need additional independent evidence if they are included in a later closed profile. A small positive corpus cannot establish all possible native behavior; unresolved required paths remain explicit.

## Windows child containment

The [process attribute API](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute) supports job assignment during process creation. The harness proposal uses a fresh job, suspended direct Python creation, explicit inherited pipe/NUL handles, queried limits and membership before resume. [Job memory limits](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_extended_limit_information) constrain committed virtual memory, not total RAM. [CPU limits](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_limit_information) measure user execution; a parent deadline separately limits elapsed work.

Owned handles govern termination and cleanup. No breakaway or settings bypass is used if association fails. Job controls are not filesystem/network isolation or full runtime authentication. Harmless controls and actual loaded identity must pass before DBN/Zstd constructors become eligible. Exact budgets and paths are in the [slice registration](../logs/native_profile_20261012_1/slice_registration.md).
