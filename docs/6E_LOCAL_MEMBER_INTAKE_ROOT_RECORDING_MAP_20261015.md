Real repeated destinations include:

## 8. Cleanup, sticky clocks and failure carriers are separate obligations

Normal `Close-RootHost`,1332–1391, first enters CleanupPhase and derives a3,000ms/global-capped deadline. For an owned started host it may call retained `Process.Kill(false)`, continue outstanding drains/ACK completion, issue bounded waits, observe signal/exit, close each retained stream, settle completed tasks, then dispose retained host/self process objects. Every actual call, poll, wait, close, full settled buffer, artifact reference, exception and terminal mutation consumes recording capacity. The256-row/1MiB ordinary reserve currently has no source-linked proof that it protects this whole suffix for every admitted prior state.

Signal, exit, EOF, GetResult, stream disposal and process disposal are independent facts. A stream-close attempt does not invent EOF or make a pending task complete. Unsettled read buffers are not snapshotted as stable completed storage. Missing artifact slots or incomplete cleanup make acceptance incomplete; a later actual tool0/full independent reader is also mandatory for any positive result. The root only manages the exact retained host Process1; native worker/job ownership and complete child cleanup belong to the host. This map does not authorize a PID-only fallback, broad kill or another native API.

Sticky clock handling is an already selected **unqualified** path, not a conforming positive RootReceipt continuation. `Get-RootClock`,58–90, retains actual current/previous raw tick/UTC fields and any conversion failure. `Invoke-RootEmergencyCleanup`,92–192, uses only retained objects: at most one Kill(false), at most64 WaitForExit(0) probes, each retained stream close at most once, each already-complete retained task GetResult once, and retained process disposal at most once per object. Its Task.IsCompleted probes remain actual status observations. No new clock, PID query, process/task creation or native proof handle is introduced there.

Emergency action records include actual results/errors and complete after-buffer storage for settled reads where captured, with unresolved task IDs and original/preceding managed exceptions. The complete diagnostic is checked against1MiB **after** these safety actions; if it cannot be built/fit/emitted, the original failure carries an explicit missing-carrier marker. It is not a proved1MiB envelope for all2,048 buffers or all exception strings, does not manufacture timestamps/complete standard rows, and cannot become mandatory-control qualification. The future root certificate must explicitly account for or honestly delimit this carrier; it must not claim that source safety fallback closes the normal recording-capacity gate.

The root receipt is sealed **after** complete host LMF1 delivery/EOF/exit and task cleanup, **before** its own persistence. The post-persistence clock/hard-end checks1488–1494 are external failure conditions; a late failure means an already written body cannot qualify without the required actual successful tool terminal. No final file-write return or self-hash command cycle is inserted into the sealed body.

## 9. Concrete evidence obligations still open

This map is future implementation input, not an execution plan, source release or positive certificate. The following necessary evidence is currently absent:

1. **Root occurrence tree:** exact Root15 nested paths and actual serialized copies, per-category extents, metadata wrappers and fixed own-digest boundary, including all external entry/wrapper/owned/tool/cohort carriers at their selected separate boundaries. 4. **Root request/ACK/copy proof:** complete pre-read/pre-write whole-body admission for the exact frame, parsed request/ACK and every repeated CIM/query/identity destination; keep raw prepared bytes separate from actual peer delivery.
