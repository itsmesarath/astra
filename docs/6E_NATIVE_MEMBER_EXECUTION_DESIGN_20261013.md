## Trust boundaries and failure rules

| Boundary | Required behavior | Does not establish |
| --- | --- | --- |
| Caller → facade | Exact registered records, immutable bytes, complete caps, every expected-pin syntax, known protocol/profile/runtime equality; no native import or child on a preflight refusal | Source authenticity or valid compressed content |
| Fixed installation → host/worker | Bounded reads of fixed registered artifacts; fresh static identity checks, fixed entry point, no data-derived path/command/import root | Full build, dependency-security or import-graph authentication |
| Host → worker | Complete immutable request via bounded read-only inherited mapping; fresh job assignment at birth; limits and exact ownership checked before resume | Filesystem/network sandbox or arbitrary hostile-process isolation |
| Native SDK → worker projections | Exact loaded associations before constructors, complete independently framed bytes, exact getter types and translations | Native parser never inspected MBO bytes before the wrapper's Metadata check |
| Worker → host | Bounded strict transport, full structural/body/pin checks, exact clean exit and empty job before positive return | A success-looking message alone proves completion |

Ordinary type/shape/pin/member/codec refusals use ValueError without partial evidence or raw-value logging. A new host lifecycle/identity-uncertainty failure uses RuntimeError, a work-budget exhaustion uses TimeoutError, and critical resource failure is not disguised as an ordinary malformed-input rejection. Never swallow AssertionError from test sentinels. KeyboardInterrupt/SystemExit must trigger exact-owned cleanup and then propagate. A valid-looking response followed by a crash, cleanup failure, nonempty job or incomplete channel is a failed invocation, never success. Do not automatically retry, shrink the member, return a successful prefix or reuse another attempt's result.

## Request transport decision

Use one **unnamed, pagefile-backed mapping**, not a temporary input file, command-line hex payload, socket or parent-to-child blocking pipe. The parent prepares the entire bounded request before process creation, then unmaps its writable view and closes its write-capable mapping handle. Only a reduced read-only inheritable handle enters the explicit child handle list. No named/global mapping, executable page or privilege change is required by this design. The child maps only the fixed bounded range for reading and closes/unmaps it after copying the complete request. This is a trusted-host construction rule, not proof against a malicious same-user process.

The selected mechanism is grounded in Microsoft's descriptions of [pagefile-backed unnamed mappings](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-createfilemappingw), [read-only mapping views](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-mapviewoffile) and [explicit-access duplicate handles](https://learn.microsoft.com/en-us/windows/win32/api/handleapi/nf-handleapi-duplicatehandle), read on 2026-10-13. These are unversioned documentation identifiers, not runtime proof. ABI constants, access rights, view/handle cleanup and denial of a writable child view need independent source-pinned declarations and new harmless controls before use. Do not infer they passed from documentation.

Proposed internal request body (not part of the public protocol): exactly `schema, operation, context, member_hex, expected_protocol_sha256, expected_profile_sha256, expected_runtime_manifest_sha256, expected_member_sha256, expected_metadata_sha256, execution_manifest_sha256, attempt_token`. Schema is `native_member_worker_request_v1`, operation is exactly `decode`. Context is the complete five-field canonical body; `member_hex` encodes the full supplied bytes in lowercase hex, never a selected suffix. The host creates a fresh 32-byte random attempt token encoded as 64 lowercase hex solely to associate the response with this invocation. Tokens/PIDs/times/handles never enter deterministic evidence or profile identity.

Mapping framing is fixed 8-byte ASCII magic `NMREQ001`, an unsigned 32-bit little-endian payload length, the complete canonical request JSON, then all-zero padding to exactly **1,048,576 mapping bytes**. Length is positive and at most 1,048,564; reject extras, wrong magic, invalid/duplicate JSON keys, invalid hex and nonzero padding. Check the complete mapping bounds before slicing or allocating from a claimed length. Command arguments contain only host-generated validated numeric handle/size values and fixed switches; none comes from member text. The request JSON and the member's original raw SHA are distinct identities.

No member data are written to stdin or a filesystem path. Parent-side preparation has bounded input/output sizes but **does not claim a parent-process memory/CPU sandbox**. The worker must remain under its job before it reads the mapping, imports native codecs or parses any request-controlled data. A child that never reads the mapping cannot block a parent request write because there is no such write after resume.

## Worker lifecycle and response

Proposed initial limits deliberately match, but do not inherit acceptance from, the old proof: one active child; process/job committed-memory limit 268,435,456 bytes; process/job user-CPU limit 50,000,000 units of 100 ns; job limit flags 0x230E; 12 seconds work and three seconds teardown; combined captured output at most 4,194,304 bytes with reads at most 65,536 bytes. Unsupported Windows/job semantics refuse before native work. No uncontained or elevated fallback.

The host uses a fixed registered base interpreter, private worker entry point, isolated/no-site/no-bytecode switches, controlled import roots/environment, hidden suspended startup, new job assigned **at process creation**, and explicit inherited mapping/stdout/stderr/NUL handles. Query limits, exact child/parent creation identity, image path, job membership and single suspended state before resume. A monotonic deadline governs the child lifecycle, not wall-clock comparisons alone. Preserve retained process/job handles; never terminate by PID alone or touch unrelated collectors.

Worker startup is stdlib-only until complete request/implementation/static-native registration succeeds. Actual DBN/Zstd loading occurs only inside this owned child; loaded associations are checked before the corresponding constructors and again at completion. Hold stable installation files for the invocation where the reviewed platform mechanism permits it, and detect/refuse before/after identity changes. Do not claim all filesystem replacement races or full imported-code authenticity are solved by hashes.

Use separate stdout protocol and stderr diagnostic channels, drained within the same bounded host loop. Stderr is bounded and must be empty for positive acceptance; never log complete input/member/price fields. Stdout contains exactly one message: `NMRES001`, unsigned 32-bit little-endian length, and canonical JSON with exact fields `schema, attempt_token, request_sha256, execution_manifest_sha256, status, evidence, failure_kind`. Schema is `native_member_worker_response_v1`. Status `complete` requires a complete evidence body and null failure_kind; status `refused` requires null evidence and failure_kind `invalid_member`. No other positive/negative variants are implicit. Length and combined output cap are checked before allocation; trailing bytes, repeated responses or premature EOF refuse.

This response grammar conveys ordinary deterministic refusal only. Worker implementation failures/assertions/native crashes/resource exhaustion must produce nonzero exit or otherwise fail the host lifecycle checks, not be flattened to `refused`. T1 must specify the exact exit-code/classification table without promising native diagnostic wording. A claimed request hash is not sufficient: the host compares its own complete request identity/token/registration and validates every evidence field/type/canonical body against held expectations.

Even after receiving a complete response, the host waits for verified owned exit, full channel termination, unchanged required identities, final empty job and successful cleanup. It releases no positive result before those checks. Receipts retain full request/response identities, exact command/image/parent/child creation, limits, timestamps, exit, teardown and cleanup observations separately from deterministic evidence. Qualification tests retain full invented inputs/outputs; the public provider has no persistent writer or raw-data log. An incomplete cleanup remains a visible failure with owned handles retained for bounded recovery; it is not declared successful termination.

## Decode and verification ordering

1. Facade validates all mandatory expected-pin syntaxes, known protocol/profile/runtime equality and exact complete Context. `verify` additionally validates the entire submitted exact record graph, status/authorities/body constraints and canonical cap before dispatch. An expected Metadata hash is syntactically early; its actual equality is necessarily later.
2. Validate exact original immutable bytes, complete length and raw expected-member equality. Prepare fixed request only after preflight; no process on an early refusal.
3. Establish contained worker and independent static/loaded identities as above. Independently frame complete Zstd input and enforce declared window/frame/cumulative limits. Decode complete nonempty frames with the qualified same-decoder exact-positive-allocation terminal-equality mechanism, not source EOF alone.
4. Independently frame the complete DBN bytes and all original header/MBO bodies. This step may inspect raw numeric bytes. It is not a Metadata-before-values parsing barrier.
5. Use one fresh explicit DBN decoder for the full decompressed member. Project and fully validate all **14 logical Metadata fields**, context and expected Metadata hash before reading any wrapper MBO property. Do not claim the native decoder did not already parse values in a returned batch.
6. Project every **17-field MBO** in original order, including every foreign instrument and explicit ts_out observation. Compare every field against independent complete wire interpretation; reconcile span bijection, counts and original mapping order versus logical getter sorting.
7. Check complete terminal state, native identities, canonical body cap and 28 False authorities; build full evidence. The host then completes its independent response/lifecycle checks before returning exact typed records.
8. `verify` dispatches a fresh complete decode after submitted preflight and compares **every body and identity**, including correctly rehashed false submissions. No cache, digest-only shortcut, replayed response or old success adoption.
