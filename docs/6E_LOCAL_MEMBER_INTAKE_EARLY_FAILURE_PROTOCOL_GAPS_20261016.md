## Minimum prospective separation

The positive predicates above must stay unchanged. The minimum repair has two separate axes: **retention/admissibility of an observation** and **qualification of the selected control**. Successful validation of framing, context and a bounded negative body must not turn a failed control into an accepted one.

1. **Closed incomplete Host observation alternative.** A prospective revision needs an explicitly discriminated alternative distinct from the existing accepted receipt contract. It must preserve every available original common observation, actual failed/unreturned operation and owner state. Its qualification stays failed or incomplete. Its exact key set, cut-state domains and associations are unresolved here; this note does not silently add fields to Host20 or overload current nulls.
2. **Closed early negative terminal transition.** Before a request exists, Root may only adopt the separately registered negative alternative with its exact version/context/pins/nonce and complete framing associations. No request, ACK, Host/Worker CIM row or accepted NoHandoff behavior follows. The existing six planned controls remain exactly six. A failed post-request attempt retains its actual request, partial ACK/query/write/flush states and negative body without pretending completed handoff.
3. **Typed negative retention independent of positive adoption.** A future Host range needs a closed positive/incomplete body union or an equally explicit separate negative range. Every range still binds the complete actual artifact, exact byte offset/length, full canonical body hash and full frame. Failed/malformed/truncated transport cannot be promoted to a valid typed body. A valid negative body does not require inventing exit0, EOF or cleanup completion.
4. **Distinct pre-GO Worker alternative.** A narrowly fitted constructor/lookup failure needs a separate negative frame/body alternative before READY. Its packet/case/nonce/source association and complete initialization/binding prefix must be explicit. Host's actual created-child identity is an external association, not a Worker self-observation. No Worker PID-return observation may be invented when the relevant binding/call was never reached. No new magic or schema name is allocated by this note.

The narrow Worker alternative can distinguish a complete returned constructor failure from a complete returned binding failure. In the source-selected prefix, constructor failure has its actual failed constructor row and no binding rows; binding failure has the successful constructor, the exact registered successful binding prefix and the one failed lookup at its actual ordinal. Later unattempted lookups have no rows. These statements do not qualify arbitrary scalar errors or assert native error semantics.

Prepared, Python-invocation-started, Python-returned/raised, error-recording-failed and unreturned/unobserved states cannot be conflated. Exact finite latch/schema domains remain a future design task. Python wrapper entry is not evidence of a hidden native constructor/lookup entry or return. If the process does not return or deliver a body, only actual outer observations can establish that absence; Root cannot manufacture the inner cut or an exception packet.

## Durable ownership and an available emitter are prerequisites

The Host and Worker need recording ownership established before a fallible `Native(...)` initialization or lookup. Caller-visible owner state must survive a raised exception and a failure while constructing its diagnostic. The actual library reference remains process-lifetime bootstrap state, not a fabricated individual `FreeLibrary` obligation. An unresolved acquisition must not be declared not-acquired merely because no handle was recorded.

At Host constructor failure, its later native job/child/pipe preparation has not yet occurred, but Root already owns the launched Host and its streams/tasks. At Worker constructor failure, Host already owns the created child, job and pipe resources. Those external ownership and cleanup obligations remain real even if the Worker cannot produce a typed packet. Reclamation by actual owned process exit is not a synthetic explicit Worker close.

A pre-GO Worker error emitter cannot depend on the unavailable or unreturned `Native.write` surface. A separately source-qualified bounded output route is needed, including its own fallible preparation/flush/close and external delivery association. As with sealed Host emission, no native return that occurs after sealing may be fabricated inside the sealed body. An exception from the emitter is not proof that the original error was completely delivered.

## Unchanged-cap limits and impossible universal retention

The existing P3 `RecordCaps`/`SchemaAdmissionPolicy`, lines183–184, remain authoritative: initialization32768; Worker result1048576; Payload/Marker262144; Host complete67108864; Root complete aggregate335544320. The Host B/H/R/M categories, complete physical copies, Root categories and external Owned/Tool/Cohort caps also remain unchanged. Reusing an existing atomic result slot would still require the explicit closed union and all its physical-copy accounting; it creates no additional allowance.

The [diagnostic envelope derivation](6E_LOCAL_MEMBER_INTAKE_DIAGNOSTIC_ENVELOPES_20261016.md) separates broad schema products, narrower source-shaped errors and unexecuted native behavior. Its source-shaped 11000-ASCII-character Windows-error counter-envelope gives a complete initialization row of33958bytes for Worker and33956bytes for Host, exceeding32768. This is **not** an observed Windows message or evidence that the constructed example is jointly native-reachable. It is enough to refute an unconditional fitting-envelope proof based solely on the current broad/source-shaped domains. The schema-supported error product is larger still and must not be relabeled source-reachable.

The current typed scalar packet admits only its fixed scalar alternatives; arbitrary complex arguments, failing attribute access, failing `str(error)`, a second reporting exception, missing delivery, process death and an unreturned operation have no universal complete fixed-size encoding. No finite cap can promise lossless arbitrary mandatory error retention. A digest, trimmed string, substitute null, opaque summary or compression does not supply a missing complete original observation.

Consequently the prospective negative design must keep these disjoint:

- **Complete supported fitted negative observation:** all required available facts are retained and fit every applicable unchanged cap; the control still failed or is incomplete.
- **Unsupported/oversize/error-recording state:** explicitly unqualified; complete available raw artifacts are retained only to the extent actually captured within their existing contracts. A marker describing missing typed delivery is not a complete replacement diagnostic or positive packet.
- **Unreturned/unobserved state:** no return, exception, EOF or internal ownership disposition is inferred. Outer actual termination/wait/stream observations remain their own evidence.

There is no universal promise here that the second or third state retains every original diagnostic. If complete mandatory data cannot be represented under unchanged caps, that branch remains nonqualifying/open. Calling it accepted negative delivery or silently dropping available fields would lower the existing bar.

## Required whole-occurrence admission

A finite complete-record/protected-suffix guarantee is possible only for a source-qualified fitted branch with a jointly proved domain. Before each entered operation it must reserve:

`complete retained prefix + every reachable next-return alternative + complete protected cleanup/emission suffix`

The reservation must charge every raw/decoded/hex/metadata copy, nested carrier, Worker-to-Host atomic result, Host-to-Root frame, parsed Host body, Root managed-read artifact, terminal duplication, external launcher/Owned/Tool copy and Cohort occurrence at its actual boundary.
